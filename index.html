Продукт 01 · Учёт рабочего времени

Табель — QR-учёт рабочего времени

Система табелирования сотрудников: REST API, веб-панель администратора, интерфейс оператора, приложение отчётов для руководителей и мобильное приложение. Отметки прихода и ухода — по подписанным QR-кодам, с проверкой геозоны офиса и автоматическим расчётом переработок.

  • PgBouncer
  • Redis 7
  • React 18 + TypeScript
  • Flutter
  • Docker Compose

Продукт 02 · Корпоративная база знаний

RAG-ассистент по внутренней документации

Локальная RAG-платформа для ответов на вопросы по корпоративной документации: FastAPI + Qdrant + Ollama + SQLite. Разворачивается в Docker Compose, работает на CPU без GPU и не отправляет данные во внешние сервисы. Каждый ответ сопровождается цитатами и ссылками на документы и страницы.

  • FastAPI
  • Qdrant
  • Ollama
  • SQLite
  • multilingual-e5-base
  • Docker Compose
  • Prometheus
Обсудить внедрение

Локальная LLM qwen2.5:3b-instruct. Есть варианты запуска на NVIDIA и Vulkan.

⌕

Гибридный поиск

Dense-эмбеддинги multilingual-e5-base плюс BM25, переранжирование, словарь синонимов и родительские фрагменты для полного контекста в ответе.

▦

Многоформатная индексация

PDF с разбивкой по страницам, DOCX/PPTX, ODT/ODS/ODP, XLSX, Office 2003, EPUB, HTML, CSV/TSV, JSON/XML/YAML и индексация сайтов.

❝

Ответы с источниками

Блок «Документация, из которой взят ответ» формируется кодом: названия документов, номера страниц и ссылки. Флаг grounded показывает отказ.

↻

Оценки 👍/👎, исправления ответов со сверкой по документации, уроки администратора, автообучение и память похожих вопросов.

⚙

Кабинет администратора

Пользователи и роли, тенанты, статистика запросов, сферы деятельности, синонимы, стартовые промты, документация из кабинета и индексация без простоя.

✓

Проверка качества

Генерация проверочных вопросов, первичное обучение по сфере, замеры латентности и супер-тест для контроля регрессий после изменений.

Продукт 03 · Мониторинг инфраструктуры

MKT Monitoring — наблюдаемость MikroTik и серверов

Стек мониторинга устройств MikroTik на Docker: сбор метрик через RouterOS API, визуализация в Grafana, алертинг в Telegram и централизованный сбор логов в Loki. Одиннадцать сервисов в общей сети собирают данные о роутерах, каналах связи, VPN, контейнерах и самом сервере.

  • Prometheus
  • Grafana
  • Loki
  • Alertmanager
  • MKTXP
  • cAdvisor
  • node_exporter
  • Docker Compose
Обсудить внедрение

RouterOS 7.x · API :8728 · syslog 514/601

◉

Метрики MikroTik без SNMP

Сбор через RouterOS API (MKTXP): 96 панелей и 73 метрики — CPU, память, температура, интерфейсы, очереди, WLAN/CAPsMAN, DHCP, BGP, firewall, netwatch.

▤

Логи роутеров

syslog-ng принимает журналы по UDP 514 и TCP 601, Promtail передаёт их в Loki, а в Grafana доступен поиск по темам и строкам.

!

Алерты в Telegram

Восемь правил Prometheus через Alertmanager: высокая нагрузка CPU и памяти, перегрев платы и CPU, недавняя перезагрузка, недоступность экспортёра, ping и задержки.

▣

Хост и контейнеры

node_exporter и cAdvisor: 44 панели Docker Monitoring — CPU, память, сеть, диск, файловые системы и PSI-метрики давления по хосту и каждому контейнеру.

⌂

VPN под наблюдением

Amnezia WG Easy с экспортом метрик: настроенные и подключённые пиры, трафик по клиентам, handshake, throughput и статистика соединений.

⚙

Один стек

Все сервисы в сети monitoring, дашборды и datasources провижинятся автоматически, данные Grafana и Prometheus лежат в понятных каталогах.

Дашборды

Grafana, основной дашборд MikroTik, логи роутеров и состояние Prometheus.

Наблюдаемость

Всё сводится в один мониторинг

MKT Monitoring закрывает сеть, серверы и контейнеры, а «Табель» и RAG-ассистент отдают health-эндпоинты и метрики. Prometheus и Grafana из MKT Monitoring собирают общую картину, алерты уходят в Telegram — без зоопарка агентов и внешних сервисов.

Табель

  • GET /api/healthдоступность API и базовая проверка сервиса
  • GET /api/readyготовность backend к работе
  • healthcheckbackend, PostgreSQL, Redis и edge-nginx в Docker Compose
  • журнал аудитавходы, изменения настроек и действия пользователей

Дополнительно: уведомления в системе (автозакрытие смен, истечение QR, ошибки офлайн-импорта) и IP-whitelist для интеграций.

RAG-ассистент

  • GET /healthliveness: статус, коллекция, модели, устройство
  • GET /health?deep=1readiness: Qdrant, алиас docs, Ollama и модель, запись в SQLite
  • GET /metricsPrometheus: HTTP-метрики, llm_retrieval_latency_seconds, llm_reindex_duration_seconds, llm_tokens_total
  • GET /reindexпрогресс переиндексации, пауза и продолжение

Метрики показывают качество работы ассистента: латентность поиска, объём токенов и длительность фоновой переиндексации.

MKT Monitoring как фундамент

Prometheus, Grafana, Loki и Alertmanager уже развёрнуты. «Табель» и RAG-ассистент добавляются как targets, а дашборды и алерты живут рядом, в одном стеке.

Данные остаются внутри

Все продукты разворачиваются on-premise. RAG-ассистент отвечает локальной моделью, логи и метрики не покидают ваш контур.

Развёртывание в Docker Compose

Стеки описаны compose-файлами, конфигурация — через .env. Обновление и перенос выполняются предсказуемо, без ручной сборки сервисов.
